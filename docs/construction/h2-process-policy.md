# 过程政策确立迭代协议（H2 / process-policy）

> Harness 段第二个迭代：把"哪些迭代需要独立评估报告"从隐性惯例变成明文规则，解决 H1 评审给出的过程可观测性 3/5。
>
> 本文件同时**补记 H1**——H1 轮在本政策确立前执行，当时未产出迭代协议。按本轮确立的规则，H 类迭代同样必须有协议，故在此追补 H1 的协议摘要（见文末），使 harness 段自身首尾一致。

## 背景

H1 轮复核发现，`evaluator-rubric.md` 的「过程可观测性」维度只能给 3/5，直接依据是两条实测：

- `docs/construction/` 下有 `c1-evaluation.md` … `c7-evaluation.md` 共 7 份评估报告，但 **G1-G7 七轮零评估报告**。
- 迭代协议只有 `c1`-`c7` + `g5`/`g6`/`g7` 共 10 份，**G1-G4 四轮无协议文档**。

根因不是"忘了写"，而是**项目从未规定过 goal 系列要不要写**。`docs/PROCESS.md` 只说"每个迭代开始前，规划者必须制定迭代协议"，对评估报告的适用范围只字未提；而该文件自身还停在 `当前阶段：inception`，已滞后整个项目周期。规则缺位下，每轮各行其是，最终沉淀成 7 轮欠账。

## 目标

- **目标 1**：在 `docs/PROCESS.md` 确立「迭代分类与评估策略」——按 C / G / H 三类定义迭代协议与独立评估报告的适用性，并给出**可判定**（而非凭感觉）的升级触发条件。
- **目标 2**：显式追认 G1-G7 为自验通过，政策自 H2 起生效、不回溯补写；同时把 G6 命中升级条件这一事实留档，作为政策生效后的判定参照。
- **目标 3**：修正 `docs/PROCESS.md` 自身的陈旧状态（阶段表、当前阶段/迭代、迭代列表）。
- **目标 4**：把 H1 发现的记录口径漂移固化成约定，防止复发。
- **不**做：回溯补写 G1-G7 的评估报告或 G1-G4 的迭代协议（用户已明确选择"定政策"而非"补文档"）；不改动任何生产代码；不调整角色划分。

## 范围

### 1. 迭代分类与评估策略（`docs/PROCESS.md` 新增段）

| 类别 | 前缀 | 定义 | 迭代协议 | 独立评估报告 |
|---|---|---|---|---|
| 构建迭代 | `C` | 新建责任区块、引入新抽象层、或需跨多个角色协作 | 必须 | 必须 |
| 目标迭代 | `G` | 在已验收架构内做增量功能，单一角色可完成，退出标准能被自动化验证完全覆盖 | 必须 | 免除，走自验 |
| Harness 迭代 | `H` | 只改过程工件与文档，零生产代码改动 | 必须 | 免除，但须刷新 `evaluator-rubric.md` |

免除独立评估报告的**论据**（写进政策，避免日后被当成偷懒）：G 类迭代的退出标准本身就是可执行断言（测试通过数 / 类型错误数 / 包体积 / 评测命中率 / 端到端返回值），任何后续会话都能重跑复现，比追述性报告更难造假；独立评估的价值在于第二双眼睛审设计，而 G 类不引入新设计决策。

### 2. 自验的最低要求（四项，缺一不得标 `pass`）

1. 迭代协议**先于开发**落盘到 `docs/construction/<迭代号>-<主题>.md`，含明确退出标准。
2. `progress.md` 留可复核验证数值（测试数 / 类型错误数 / 包体积含差值 / 评测命中率 / 端到端 smoke 实际返回值）。
3. `feature_list.json` 对应条目 `evidence` 非空且指向具体证据。
4. 通用退出检查（双层可观测性）逐条过。

### 3. 升级为独立评估的触发条件（四条，命中任一即升级）

- 破坏性接口变更（函数签名 / HTTP API 契约 / IPC 协议不兼容修改）
- 持久化 schema 迁移（SQLite schema / ES mapping / 配置文件 schema 版本变更）
- 新增数据源类型或 embedder 后端
- 触及安全边界（凭证存取 / 进程边界 / 文件系统访问范围）

论据：这四类改动出错的代价不由当轮承担，而是转嫁给未来会话或用户数据；自动化断言只能证明"当前测试通过"，证明不了"迁移路径对老数据安全"。

### 4. 记录口径约定（`docs/PROCESS.md` 新增段）

- 测试数一律以 `npm run test:unit` 为准（带 `KB_MILVUS_URI=./kb_milvus_lite.db`，Milvus 8 项全跑）。
- 包体积以 `npm run build` 的 Vite JS 行为准，记录带前值与差值。
- `evaluator-rubric.md` 每轮收尾同步；连续两轮未同步即判过程可观测性不合格。
- 新增维度不得长期挂"待评分"；暂缓须写明解除条件与预计轮次。

### 5. `docs/PROCESS.md` 自身状态修正

- 阶段表：启动/细化/构建/移交四行 `待进入` → `已通过`；新增「移交后增量」行覆盖 G/H 系列。
- 当前阶段：`inception` → `移交后增量（transition 已通过）`；当前迭代 → H2。
- 迭代列表：7 行 → 21 行，补全 C5-C8 / G1-G7 / H1-H2，新增「类别」与「状态」列。
